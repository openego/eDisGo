# OEP-dependent test inventory

This is a static inventory of tests that currently reach the live OEP, directly or through a higher-level eDisGo function. It is based on commit `1d2b5de9af1d1636c0456ce17f5698e08957301e` and contains **38 tests**.

`Test Type` is the directory below `tests/`; `root` means that the test file is directly in `tests/`.

The dimensions are the results asserted by the tests. Data volume is a lower-bound estimate of the logical result data, not a measurement of HTTP traffic, PostgreSQL transfer size, geometry size, or pandas memory. Numeric estimates assume 8 bytes per value. OEP array columns usually contain a full year even when a test later selects only a few hours.

### Detailed

The final two columns separate two independent questions:

- `Test scope` describes which part or level of eDisGo the test exercises.
- `Proposed OEP treatment` describes whether live OEP access should remain.

The scope labels may be combined where a test currently covers more than one level:

- `Transformation` or `Domain`: eDisGo calculations and data-processing rules.
- `Integration`: cooperation between several eDisGo components.
- `Public API`: behavior exposed through user-facing Python methods.
- `End-to-end`: a complete user workflow such as executing an example notebook.
- `OEP query/interface`: the boundary that constructs a live query and converts its response.

The proposed treatments use five consistent options:

- `Offline with local data`: use a minimal local dataset and remove the `oep` marker.
- `Offline with mocked retrieval`: mock only the external retrieval boundary and remove the `oep` marker.
- `Retain as live contract`: keep a small, bounded live OEP test.
- `Split`: keep a small live contract and move transformation or integration checks offline.
- `Remove or convert offline`: eliminate duplicated live coverage.

## Important limitations

- This is a static source audit. The proposed runtime guard is still needed to find indirect or future OEP requests.
- Exact network transfer volumes cannot be inferred reliably from dataframe shapes because the OEP stores many time series as arrays and several queries return geometries, JSON, or strings.
- Dimensions and exact row-count assertions describe the current test grid and mutable OEP state. They should not automatically become requirements for the retained live contract suite.
- The table lists the columns selected or used by current queries. A few imports currently select complete records, most notably `egon_ev_metadata`; those queries can be narrowed when the tests are refactored.
