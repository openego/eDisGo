Release v0.3.1
================

Release date: not yet released

Changes
-------

* Corrected the Julia version documented in ``config_opf_julia.cfg``, which still
  pointed at ``julia-1.1.0/bin`` while the bundled ``eDisGo_OPF.jl`` package targets
  Julia 1.12. The file is included verbatim in the configuration reference, so the
  stale path was published in the documentation. Its ``julia_bin`` value has not been
  read since :meth:`~.edisgo.EDisGo.pm_optimize` started resolving ``julia`` from the
  system ``PATH``; the reference now says so instead of claiming the file points to the
  binary in use
* Fixed the documented fall back from OPF versions 3 and 4 to version 2 never working:
  the first overlying-grid read in :func:`~.io.powermodels_io.to_powermodels` sat
  outside the ``try``/``except IndexError`` that implements it, so an empty
  ``overlying_grid`` raised ``IndexError: single positional indexer is out-of-bounds``
  instead of degrading gracefully. A grid without district heating, whose central heat
  pump series is legitimately empty while the rest of the overlying grid is populated,
  is now filled with zeros rather than losing the high-voltage requirements for the
  whole grid
* Switched ``spatial_reduction_opf`` to ``opf_version: 3``. The preset runs
  ``import_overlying_grid_data`` but optimised with version 2, which does not build the
  high-voltage requirement constraints, so the imported overlying-grid setpoints only
  reached the OPF as generator time series and the flexibility setpoints were discarded
* Rewrote the header of the ``spatial_reduction_opf`` preset, which described a
  preset of a different branch: it referred to itself as "UC6", explained a port from
  ``edisgo_run_edisgo``'s ``uc6_spatial_reduction.yaml``, advised porting a "uc5
  feature" for automatic timestep selection that this branch has had all along as
  ``select_critical_timesteps``, named a branch this is not, and called
  ``spatial_reduction.enabled`` false by default where the preset itself sets it
  true. It now says what the preset is for — the standalone CSV and fixed-window
  sibling of ``overlying_grid_opf_spatial`` — and both presets no longer claim that
  eGo can inject the ``spatial_reduction`` block, which it cannot
